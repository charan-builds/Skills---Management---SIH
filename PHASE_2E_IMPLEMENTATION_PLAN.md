# PHASE_2E_IMPLEMENTATION_PLAN.md

## 1. Executive Summary
Phase 2E formalizes the **Recommended Upskilling** capability. It maps verified Skill Gaps (produced by the Phase 2D `SkillGapService`) to existing `TrainingProgramme` entities. This is a deterministic mapping based purely on verified deficit vs. defined programme capability. It explicitly enforces the Zero-Fabrication rule, preventing AI hallucinations, guessed mapping, or ATS job matching functionality.

## 2. Current State Audit & Conflicts
*   **Existing Architecture**: The system already possesses a functioning `SkillGapService.generate_recommendations` logic and a corresponding `/api/trainees/{id}/recommendations` endpoint.
*   **Existing UI**: The frontend component `TraineeRecommendations.jsx` correctly maps the explicit response states.
*   **Programme Model**: `TrainingProgramme` objects contain `skills_taught_structured`, which outlines explicit `skill_id`, `skill_name`, and `target_level` metrics.
*   **Conflicts Found**: None that violate the Phase 2 boundaries. The current state is already clean and strictly devoid of recruitment logic. However, Phase 2E formalization requires ensuring deterministic prioritization, handling of multiple gaps mathematically, and absolute null-safety.

## 3. Authoritative Input (Phase 2E Boundary)
Phase 2E is allowed to consume ONLY:
*   `gap_size`: The numerical deficit generated by Phase 2D.
*   `skill_id` and `skill_name`: The explicit identity of the gap.
*   `priority`: (CRITICAL, HIGH, MEDIUM, LOW) derived from importance + gap size.
*   `target_level`: The explicit capability defined in `skills_taught_structured` on the Programme entity.
*   **Forbidden**: Candidate matching data, popularity heuristics, fabricated mappings, and AI-generated text without deterministic proof.

## 4. Programme-Skill Mapping Contract
A programme demonstrably addresses a gap IF AND ONLY IF:
1.  The programme's `skills_taught_structured` array contains a skill matching the gap's `skill_id` or case-insensitive `skill_name`.
2.  The `target_level` of that taught skill is >= the benchmark's `required_proficiency`.

**Behaviors**:
*   *Incomplete Metadata*: If a programme lacks `target_level` or the skill is only present as a flat string, it is assumed insufficient unless otherwise proven.
*   *No Matching Programme*: Explicitly yields `NO_MATCHING_PROGRAMME`. No guesses are made.

## 5. Deterministic Recommendation Algorithm
1.  Obtain Phase 2D `SkillGapBase` list. Filter out gaps where `gap_size` <= 0 or `gap_size` is `None`.
2.  Iterate over remaining valid gaps.
3.  For each gap, iterate through all active `TrainingProgrammes`.
4.  Filter programmes that satisfy the Programme-Skill Mapping Contract.
5.  Calculate `expected_impact = target_level - gap.current_proficiency` (If `current_proficiency` is missing but gap exists, impact defaults to 0).
6.  Sort valid programmes by `expected_impact` (Descending) -> Tie-breaker: Programme Name (Alphabetical).
7.  Select the top programme for the specific gap.
8.  Return explicit states: `RECOMMENDATION_AVAILABLE` if found, `NO_MATCHING_PROGRAMME` if no programme meets the threshold.

## 6. Multiple Gaps & Ordering
*   **Recommendation Granularity**: Recommendations are generated per-gap. If a trainee has 3 gaps, they will receive 3 distinct recommendation objects (or empty states).
*   **Programme Duplication**: A single high-value programme *can* be recommended multiple times across different gaps if it adequately bridges all of them.
*   **Priority Effect**: The resulting array of `UpskillingRecommendationBase` objects will inherit the exact sorting order of the Phase 2D Gaps (Critical -> High -> Medium -> Low), ensuring the Trainee addresses the most severe gaps first.

## 7. Zero-Fabrication Enforcement
*   **No Benchmark**: `target_role_id` is null -> `NO_BENCHMARK`.
*   **No Evidence**: Trainee lacks assessment for the skill -> `NO_EVIDENCE` (Gap size = `None`). Recommendation engine skips.
*   **No Gap**: `gap_size` <= 0 -> `NO_SKILL_GAPS`.
*   No algorithm shall inject "Recommended for you" generic programmes simply because the array is empty.

## 8. Prioritization
Prioritization relies 100% on the `importance` coefficient defined by the Phase 2D Benchmark Role, multiplied by the numeric severity of the gap. No external "labour market demand API" is queried to shuffle the ordering.

## 9. API Contract
*   **Endpoint**: `GET /api/trainees/{id}/recommendations`
*   **Authorization**: `ensure_trainee_access` (Only self or Admin).
*   **Response Schema** (`List[UpskillingRecommendationBase]`):
    *   `gap_id` (str)
    *   `skill` (str)
    *   `state` (str: `RECOMMENDATION_AVAILABLE`, `NO_MATCHING_PROGRAMME`, `NO_BENCHMARK`)
    *   `recommended_programme` (Optional[str])
    *   `programme_id` (Optional[str])
    *   `provider` (Optional[str])
    *   `expected_impact` (Optional[int])
    *   `reason` (str)

## 10. Frontend Contract
The `TraineeRecommendations.jsx` component MUST display:
*   A clear banner if `NO_BENCHMARK` is returned, with a CTA to update the profile.
*   Empty state `CheckCircle` if `NO_SKILL_GAPS` is returned.
*   Individual cards mapping Gap -> Programme.
*   Clear visualization of `expected_impact` (e.g., "+15 Proficiency").
*   Explicit "No Match" UI if a gap exists but no programme teaches it.
*   No job portal buttons or "Apply to Job" CTAs.

## 11. Security Model
*   **Isolation**: `Depends(get_current_user)` checks if `uid == id` or `role == 'admin'`.
*   **Data Leakage**: The recommendation array contains NO data regarding other trainees or employer candidate shortlists.

## 12. Test Matrix (Phase 2E Scope)
1.  **No benchmark**: Returns `[]` or explicit `NO_BENCHMARK` schema.
2.  **No verified evidence**: Gap evaluates to `None`, recommendation skips.
3.  **No skill gap**: Gap is 0, recommendation returns empty list.
4.  **One skill gap + matching programme**: Standard success.
5.  **One skill gap + no matching programme**: Yields `NO_MATCHING_PROGRAMME`.
6.  **Multiple gaps + one programme covers multiple**: The same programme ID appears across multiple gap recommendations.
7.  **Multiple gaps + different programmes**: Distinct programmes recommended.
8.  **Programme has unrelated skill**: Ignored in mapping.
9.  **Programme has incomplete skill metadata**: Assumed insufficient.
10. **Programme skill proficiency is insufficient**: `target_level` < `required_proficiency` -> Rejected.
11. **Duplicate programme mappings**: Max `target_level` resolution.
12. **Invalid skill IDs**: Gracefully ignored.
13. **Unauthorized trainee access**: 403 Forbidden.
14. **Recommendation ordering/tie-breaking**: Sorted by expected impact.
15. **Zero-fabrication regression**: Verify no generic fallbacks exist.
16. **Phase 2D regression**: Run all 140 existing tests to ensure no breakages.

## 13. Migration & Rollback
*   No schema migrations required as the response payload strictly aligns with `UpskillingRecommendationBase`.
*   **Rollback**: The current code already essentially reflects this exact logic. Any regressions discovered during tests can be reverted securely using Git history.

## 14. Acceptance Criteria
*   The deterministic algorithm passes all 16 test matrix scenarios.
*   Zero occurrences of ATS/job-matching behavior are restored.
*   Zero random or "fallback" recommendations are served.
*   Explicit states correctly surface to the UI.
